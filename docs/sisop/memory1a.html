Load and free programs, then switch the memory model. The same history of loads and frees is replayed under each model, so you can see what each one wastes and what each one refuses to load. Swap a process out and back in to watch it move. The Virtual memory tab keeps only some pages of each process in RAM, with a TLB in front of the page tables. Page table sizes compares flat, multi-level and inverted tables, and Thrashing shows what happens when too many processes share too few frames.

        TLB

        Entries are tagged with the process, so switching processes does not empty the TLB. When a page is evicted from RAM, its TLB entry is removed too. The least recently used entry is replaced.

        Page tables

        P present in RAM · U use bit, set on every access · M modified (dirty), set on a write. A page with P = 0 is on disk. Dots mark pages the program does not use. W marks the working set W(t, Δ): the pages the process used in its last Δ accesses.

          The numbers behind the chart

          Each process gets an equal share of the frames and replaces its own pages with LRU. It also waits for ordinary I/O about every 300 accesses. The paging disk serves one fault at a time.

          L is the mean number of accesses between page faults; S is the disk time per fault. Denning's L = S criterion and the 50% criterion (paging disk busy about half the time) are rules of thumb for steering toward the peak without measuring CPU use. Compare their rows with the peak row. Time is counted in memory accesses: one access takes one unit.
